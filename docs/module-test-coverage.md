## Inventory and risk

Inventory authored Kotlin/Java under `src/main`, excluding generated/build/runtime files. A logical family is library + common/Fabric/Forge branch + relative source path; version overrides replace shared files and are not counted twice. Distinct loader implementations remain distinct families. LOC* counts the largest physical variant, including comments/blank lines: a sizing aid, not executable coverage. Prioritization: storage conservation and failure reporting first; persistent upgrade state, native loader/platform dispatch and fake-player cleanup next; data generation and public compiler contracts after that. ## Significant decisions and demonstrated changes

- Tests requiring Minecraft transformation/registries run in native loader GameTests rather than swallowing bootstrap exceptions in JUnit. Pure geometry/storage policy/compiler checks retain their existing small test harnesses.
- Peripheralium owns its tests, but its loader build scripts connect their outputs to the existing Tweakium integration runner. This avoids duplicate server scaffolding and reverse production dependencies. Its real matching loader entrypoint and common outputs are loaded; Forge-family runs explicitly declare the production mod. Test outputs are not publication dependencies.
- Peripheralium's blend item and smelting recipe are deliberately legacy-only in the source. Tests preserve that version difference rather than creating a false parity regression.
- A GameTest process exit of zero is insufficient: the build deletes stale XML, requires a fresh nonempty report, checks declared counts and rejects failures/errors. Testiarium's optional negative fixtures additionally require the exact intended skipped-case identity and sentinel, not an unrelated failure or accidental success.
- Modern pocket/turtle reconstruction now distinguishes an unspecified component from an explicitly removed one. A removal must survive item serialization relative to the crafting template without mutating that template. Both regressions failed with `Explicit removal restored the crafting default` before the paired fix.
- Entity drop capture retains the configured entity rather than clearing it. Both versions failed the target-specific capture regression before the one-line fix; the test also checks unrelated entities, cleanup, and exact rejected remainder.
- Earlier preserved fixes cover XP inverse arithmetic, lowercase relative sides, query-pull destination forwarding, numeric destination bounds and exception-safe global drop capture. These changes are retained with their behavioral tests, not accepted on worker status alone.
- Reverse Fabric mutation previously inserted the replacement snapshot additively: inserting three items into ten produced 23 instead of 13, and abort could not restore contents. The explicit loader-neutral `ReplaceableItemStorage` capability now distinguishes exact restoration from ordinary additive `store`. `ContainerWrapper` implements copy-on-replacement; Fabric adapters take detached snapshots, refuse unsupported backing contracts or unrepresentable existing stacks before mutation, and preserve native Fabric slot transactions via `FabricStorageUtils.getSlot`.
- Exact replacement guarantees are bounded: backing slot layout, contents and maximum must not independently change during an open transaction; extraction must be permitted and previously captured variants restorable. Native container setter notifications can occur during speculative mutation/rollback and are not themselves rolled back. Arbitrary storage wrappers do not acquire transactional guarantees merely by implementing the ordinary slotted API.
- A real Team Reborn lookup reproduced `NoSuchMethodError: ResourceLocation(String)` on 1.21.1 with energy API 3.0.0. The catalog now retains 3.0.0 for legacy Minecraft and selects compatible 4.1.0 for 1.21.1 only. The resolved 4.1.0 JAR matched the official Maven download by SHA-256; required native absence-lookup regressions pass on both versions. No energy-transfer claim is inferred from absence handling.
- Testiarium's legacy fail-fast wrapper rethrows through native `thenExecute`, setting the parent failure immediately instead of waiting for timeout. Required outer observers cover native assertion, ordinary exception and assertion-error paths, one execution, blocked later callbacks and delayed competing success. Container assertions reject nonempty expectations beyond capacity while accepting empty padding. Registration tests restore both native registries and private registered classes in `finally`.
- TypeScript contracts check exact inferred results, reject `any` erasure, exercise inventory/item-storage overloads, all five scanning modes and both wrapping overloads for all nine providers. Mutation replay detects 66 of 67 variants; all 12 negative directives independently produce their intended diagnostic. Nullable-return removal remains undetected because enabling strict null checks exposes five dependency-source errors; no suppression or dependency patch hides that boundary.

## Remaining risk boundaries

This is not exhaustive gameplay verification. Client rendering, network handshakes, interactive menus, multiplayer concurrency, true chunk/disk unload/reload, installed pocket/turtle transitions and third-party protection/storage implementations have not been established by these server/unit tests. Representative coverage of a large logical module does not imply every subfeature passed.

The audit also identified source risks beyond the focused fixes: fake-player provider cleanup/reconciliation after exceptional callbacks, nested-NBT subset comparison, block-codec boolean persistence, empty/malformed query combinators, storage rejection after simulation, and optional CCT sequential-action scheduling/publication ordering. These are explicitly retained as follow-up investigations; absent native reproductions must not be described as confirmed fixed defects. No Minecraft 26.1 implementation, remote publication, push or primary-branch merge belongs to this coverage card.

The inherited npm dependency audit reports one high-severity `picomatch` advisory. Dependency remediation was not included in this test-contract change; the audit and dependency explanation were preserved separately. Passing compiler contracts are not a clean dependency-security audit.
